Purpose

Bridge hoje relaia megaAPI (WhatsApp não-oficial) ↔ Chatwoot. Adicionar WaBlast (api.wablastmessage.com, gateway oficial Meta Cloud) como 2º provider, aditivo. Operador escolhe provider por tenant no wizard; os dois coexistem no mesmo Chatwoot (slugs/inboxes distintos).

Cliente WhatsApp↔ gateway (megaAPI | WaBlast)↔ bridge /v1↔ Chatwoot API-inbox↔ agente

Problem

Código hardcoded em megaAPI: processInbound/processOutbound, colunas megaapi_*, rotas /v1/wa+/v1/cw. Sem seam de provider. WaBlast difere em 4 pontos que quebram reuso direto:

DimensãomegaAPI (atual)WaBlast (novo)
Auth inboundBearer via ?token=Standard Webhooks (webhook-id/timestamp/signature, HMAC-SHA256, secret whsec_)
Mídia outbound1 passo (manda URL)2 passos: upload POST /v1/media → media_id → POST /v1/messages
Mídia inbounddownloadMediaMessage (POST)GET /v1/media/{id} (Bearer wak_)
Janela 24hignora (não-oficial)free-form fora de 24h → 409 WINDOW_CLOSED

Solution

Seam mínimo Provider (interface justificada: convention libera na 2ª implementação real). Cada gateway isolado em 1 arquivo. megaAPI vira wrapper das funções atuais — zero mudança de comportamento. processInbound/processOutbound ficam provider-agnósticos via providerFor(t).

// internal/bridge/provider.go
type InboundMessage struct {
    ContactID  string      // digits sem "+" (== waContactJID)
    Name       string
    Text       string
    Attachment *Attachment // nil se texto
    ExternalID string      // messages.external_id (idempotência)
}
type Provider interface {
    SendText(ctx context.Context, t Tenant, to, text string) error
    SendMedia(ctx context.Context, t Tenant, to string, a Attachment) error
    ParseInbound(body []byte) (InboundMessage, error)
    DownloadMedia(ctx context.Context, t Tenant, a Attachment) ([]byte, string, error)
}
func (s *Server) providerFor(t Tenant) Provider // switch t.Provider
var errWindowClosed = errors.New("wablast: 24h window closed")

Requisitos (EARS)

REQ-1 (ubiquitous): The bridge shall support provider wablast alongside megaapi, selected per tenant via column provider.
REQ-2 (state-driven): While tenant provider is megaapi, the bridge shall behave byte-identically to today (regression-free).
REQ-3 (event-driven): When WaBlast POSTs message.received to /v1/wab/{slug}, the bridge shall resolve the Chatwoot contact+conversation and post an incoming message.
REQ-4 (event-driven): When a Chatwoot agent sends an outgoing message on a wablast tenant, the bridge shall relay it via POST /v1/messages (text) or media upload+send (2-step).
REQ-5 (event-driven): When inbound media arrives, the bridge shall fetch bytes via GET /v1/media/{id} and attach them to the Chatwoot message.
REQ-6 (unwanted): If WaBlast returns 409 WINDOW_CLOSED on an agent reply, then the bridge shall mark the message failed (non-retriable) and post a private note instructing template use.
REQ-7 (unwanted): If the inbound Standard-Webhooks signature is invalid or webhook-timestamp is older than 300s, then the bridge shall reject with 401.
REQ-8 (unwanted): If WaBlast webhook registration returns no whsec_ during wizard create, then the wizard shall hard-fail with a 400 PT-BR and not persist a half-configured tenant.

Detalhe: telefone inbound

Verificado no source WaBlast packages/core/src/webhooks/mapper.ts:59 (from: message.from): from = wa_id cru Meta = dígitos sem + (ex 5511999990000), igual à saída de waContactJID. cwCreateContact ("+"+jid) fica correto. ParseInbound passa direto com strip defensivo de +. Sem ++ nem identifier divergente.

Loop-prevention

Assinar só message.received (ignorar message.echoed/status) = equivalente WaBlast do check fromMe do megaAPI. Sends do bridge não re-entram.

Riscos / edge cases

  • Endpoint duplicado: POST /v1/webhooks é create (não upsert). Re-rodar wizard cria 2º endpoint. Mitigar: pré-check GET /v1/webhooks. Impacto limitado (UNIQUE em messages dedup; órfão auto-desativa após 15 falhas).
  • Mídia inbound TTL: Meta apaga ~7d → 410. Bridge baixa on-demand no processInbound; delay grande de fila pode expirar → notRetriable + log.
  • HEIC/GIF: prepareMedia (megaAPI) barra pré-envio; WaBlast confia no 422 META_ERROR → notRetriable (aceitável MVP).
  • Colunas NOT NULL: migração precisa relaxar megaapi_* ou inserir zero-values; validado na Fase 1 com tenant legado.

Fora de escopo (MVP)

  • Template automático ao fechar janela 24h (só nota agora).
  • Eventos WaBlast além de message.received (delivery/read/failed → CSAT/nota futuro).
  • Canal whatsapp_cloud nativo do Chatwoot (WaBlast é o gateway — não é o caminho).
  • megaAPI + WaBlast no MESMO tenant.

Dependências

Nenhuma lib nova. Reusa crypto/subtle, crypto/hmac, net/http/httptest, mime/multipart. Env nova: WABLAST_BASE_URL (default prod).
